
FBNEO_PLUS 核心 (FBNEO 1.0.0.03)  

核心项目 https://github.com/lrf739146825/FBNeo/

  名词解释: 
    1.IPS: 原版rom的改版补丁，[原版rom + IPS补丁 = 改版]。可在此项目获取: https://github.com/taoenwen/FBNeo_IPS
      本质:加载ROM和IPS后，在内存里把补丁打上，然后运行。
    
    2.Romdata: 借用已收录的rom加载流程，替换驱动定义，使得rom能够运行，[未定义的rom + Romdata定义 = 可识别运行]，
      本质:临时替换被借用的ROM的驱动列表，当作那个ROM来运行。
      运行Romdata不需要被借用的rom的zip文件参与，且不适用于被第三方特殊加密过的rom。
    
    3.运行所需rom资源: bios,游戏rom,游戏rom的主rom。
    
    4.RA根目录的/system/目录: 此目录为RA默认的BIOS目录，不同平台可能有所差别，以RetroArch主菜单->设置->文件夹->系统/BIOS 所显示的路径为准。

  官方特性:
    1.核心选项-> 允许修补集组(Allow patched romset): 
      允许RA根目录的/system/fbneo/patched/目录中的rom的内部文件逐一覆盖启动时加载的同名rom的内部文件，只会覆盖大小和名称匹配的文件，被覆盖的文件不会校验crc。
      如果patched目录放置的zip是完整的rom，包含原版rom的所有文件，那么加载其他地方的同名rom内部文件会被完全取代，等价于直接加载此处的rom并忽略crc。
      简单的说就是把rom放此处，直接从这里加载没有crc校验。在其他路径新建一个空文本文件改成zip也能启动位于patched目录的同名rom。

      存储卡命名规则: 以"rom名_p几_"开头,以.pgm2或.bin结尾。 示例：orleg2_104cn_p1_.bin , kov2nl_302cn_p1_正关羽.bin

      选项介绍：
        "空插槽"：不使用任何卡片。
        "默认卡片"：文件名称结尾为"_default"，选择此项会应用default存储卡文件，文件缺失时会自动创建。
        "临时卡片"：不会生成存储卡文件，仅作为解锁插卡人物选择限制的方式，退出游戏后失效，方便重开游戏体验不同的角色。重启游戏不算退出游戏。
        "新建卡片"：文件名称结尾为"_时间戳"，可以创建多份。
        "最新的新建卡片"：由于新建的卡片需要重新加载游戏才会添加到下方的卡片文件列表中，所以使用此项来指代最新创建的卡片，供选取和立即应用最新创建的卡片。
        除了default文件，所有名称匹配的存储卡文件都会罗列在菜单下方以供选用。存储卡按照文件名称自然排序，每个游戏的每个玩家存储卡最多显示120个。
  
  补充说明: 
      1.IPS与Romdata是FBNEO RetroArch核心和Windows独立模拟器都具备的功能。

      2.CRC的存在是为了确保，即便新版核心里驱动文件名称变了，依旧能通过CRC匹配成功加载文件名称还是旧版的rom。
      
      3.关于rom的驱动文件是否正确。zip内部对应的文件大小不匹配直接失败; 新rom和老rom文件名称上可能会变动，但只要CRC能够匹配上，核心就能找到对应的文件，游戏依旧能够正常运行。
      
      4.新的改版游戏应该使用IPS 或 新rom名+Romdata的方式，而非占用原版的rom名. patched目录应该成为一种临时手段。
      
      5.IPS一般只匹配文件名，这也是旧版IPS在新版rom上会失效的原因，需要把文件名重新匹配上。
      
      6.原版rom会加载多少文件是在驱动列表定义好的，除非直接修改源码，添加扩容的文件名进驱动列表，不然即便扩容的zip用的是原版的rom名，加载的文件数量也是不会变的。
        想要改变加载的: 文件名称、文件数量、文件的大小，需要借助Romdata。
      
      7.Romdata生效前提是你用的rom名不能和原本支持的rom名重复，加载zip文件的逻辑如下: 获取zip名称，如果是原本就支持的rom就按原本的流程加载，
        如果rom名称是未知的，则开始查找是否有与之匹配的Romdata的.dat文件，有就走Romdata方式加载。

  PC端FBNEO独立模拟器使用说明: 
    
    1.汉化设置: 
      下载汉化文件地址 https://bbs.xqemu.cn/forum.php?mod=viewthread&tid=1591  
      下载 localisation.zip  将里面的文件放置于FBNEO根目录/support 目录内即可，拳皇97的游戏IPS目录为kof97
      启动FBNEO独立模拟器,
        设置界面语言为中文: 菜单栏"misc"-"UI Language"-"Select UI Language" 选择 "Chinese (Simplified).flt"
        设置游戏列表中文: 菜单栏"misc"-"GameList Language"-"Select gamelist Language" 选择 "Chinese (Simplified)_gamelist.glt"
      
    2.IPS与Romdata用法: 
      
      IPS用法: 将存放对应游戏IPS的文件夹放入\support\ips\目录内，拳皇97的游戏IPS目录为kof97,MD的大航海时代2日版的IPS目录为md_daikok2，以游戏的文件名称为准。
                               点击菜单栏->游戏->载入游戏->点选需要启动的游戏(选中后可以在信息栏中看到游戏的文件名称，家用机会有机种前缀)->点击右下角的ISP管理器勾选需要的IPS补丁点击确定->勾选应用补丁->进入游戏即为IPS版本。
     
      Romdata用法: 将Romdata的.dat文件放置于\config\romdata\目录内，将rom放置于\roms\romdata\目录或对应机种分类的目录内。
                                   点击菜单栏->游戏->从Romdata载入游戏—>选择要启动的.dat文件即可。
    3.画面滤镜设置: 
      参照这个项目和配套说明: https://github.com/lrf739146825/FBNeo_Shaders
    
    4.Rom资源 
      https://lolroms.com/  
      https://pleasuredome.github.io/pleasuredome/nonmame/fbneo/index.html
      https://www.retroroms.info/index.php
    
    5.即时存档功能 菜单栏 "Game"->"save states"  
       (1)."save sate" 即时存档生成在根目录\savestates文件夹   
       (2)."load sate" 加载即时存档
    
    6.联机游玩
      https://kaillerareborn.github.io/
      
      下载 Open Kaillera 客户端，放置于FBneo根目录
      64位客户端 kailleraclient.dll 或 kailleraclient64.dll
      32位客户端 kailleraclient.dll 
      
      实际上32位也可以用kailleraclient64.dll这个名称，但不推荐这么做。
      
      在菜单栏 Game -> Play via kailleraclient 即可打开联机客户端
      客户端右上角默认为 n02.kaillera 远程服务器联机; n02.p2p 局域网联机; n02.player 记录回放(存放于根目录/records)
      
      在n02.kaillera模式下，如果有明确的服务器地址端口，可以在IP栏输入，点击connect连接。也可点击 servers list 使用公用服务器进行联机游玩。
      Nick栏为玩家联机昵称，建议修改，同一个联机服务器里的昵称不能重复，否则会冲突
      房主建房，建房时可选的游戏为FBNEO已经扫描到的游戏，参与游玩的玩家都进入房间后，房主开启游戏，1P玩家使用1P的投币键，2P玩家使用2P的投币键，各个玩家都使用各自客户端的1P游戏键位。
      
      联机要求: 模拟器版本一致，游戏rom版本一致。

    7.PGM2插卡用法：菜单栏  Game -> Memory Card

一、把核心添加进RA

    1.把对应平台的核心文件复制进RA根目录的cores文件夹。
    2.文件核心信息文件.info需要复制进RA根目录的info文件夹。为了避免缓存数据干扰，可以删除info文件夹里的core_info.cache文件。
    3.核心文件和核心信息文件添加完毕后重启RA。
    
    Android端由于默认配置目录存在访问限制，没法直接复制粘贴添加核心和info文件。
        1.确认手机使用哪个版本的核心,打开RetroArch->系统信息->系统信息->CPU架构，如果值为ARMv8，则使用arm64-v8a核心版本
        2.手动添加核心或更新核心: 
          "加载核心"->"安装或还原核心"
        3.变更info文件夹目录: 
          "设置"->"文件夹"->"核心信息"处修改核心信息文件的存放位置，可以修改到手机存储根目录Retroarch/info/下。
          主菜单"在线更新"-"更新核心信息文件",把官方核心配套的info文件下载到新的info目录内。
        4.把.info文件添加到重新指定的info目录内。fbneo_plus_libretro.info文件使得核心可以在RetroArch菜单里加载.dat文件。
        5.重启RA


★★★ FBNEO_PLUS核心在Retrorch的主要用法★★★

1.添加IPS只需往 Retroach根目录/system/fbneo/ips/ 目录处添加,ROM的IPS需要存放在与ROM同名的文件夹内(kof97文件夹存放kof97.zip的IPS)。
  启动游戏后，在核心选项里切换对应的IPS版本。

2.添加Romdata，只需要把zip和.dat文件放在同一目录内，或把.dat文件放在Retroach根目录/system/fbneo/romdata/目录
  直接加载zip文件启动。
  
 ⭐补充说明: 在windows系统里，Retrorch根目录下的/system目录为Retrorch的默认BIOS路径。其他平台可能有所差异，
            以[Retrorch的设置->文件夹->系统/BIOS]所指定的路径为准。
            
            如果把[Retroch的设置->核心->系统文件在游戏文件夹中]此项开启，那么BIOS目录会变更为启动游戏时ROM所在的目录，即rom所在的目录等价为system目录。

三、功能使用

    1.FBNEO的ROM和BIOS有效检索路径: (1)被加载rom所在的目录 ,(2)RA根目录下的/system/ ,(3)RA根目录下的/system/fbneo/ ,
      (4)RA根目录 /system/fbneo/path/rom_path.opt 配置的扩展路径 ,(5)上述4个路径的派生子目录
            
        派生子目录: 
        - "arc"，"arcade"，
        - "romdata"，
        - "coleco"，"colecovision"，
        - "gamegear"，
        - "megadriv"，"megadrive"，"genesis"，
        - "msx"，"msx1"，
        - "pce"，"pcengine"，
        - "sg1000"，
        - "sgx"，"supergrafx"，
        - "sms"，"mastersystem"，
        - "spectrum"，"zxspectrum"，
        - "tg16"，
        - "nes"，
        - "snes"
        - "fds"，
        - "ngp"，
        - "chf"，"channelf"
        
        例如:  /system/fbneo/arc/  或 /system/fbneo/arcade/ 或 /system/fbneo/romdata/

    2.IPS 
        <<核心选项加载IPS需要在"核心选项"里开启 "允许修补集组(Allow patched romset)"解锁功能的使用>>
        默认放置于 RA根目录 /system/fbneo/ips/ ，文件夹名称要与对应的rom名称匹配。
        IPS的.dat文件可以被直接加载运行，前提是运行所需rom资源皆可被寻得。
        运行与IPS文件夹名称匹配的rom时，可在核心选项里勾选IPS(可多选)。
        直接加载.dat文件，要求"运行所需rom资源"在"有效检索路径"里。
        
    3.Romdata 
        <<核心选项加载Romdata需要在"核心选项"里开启 "允许修补集组(Allow patched romset)"解锁功能的使用>>
        默认放置于 RA根目录 /system/fbneo/romdata/ ，.dat文件内部的ZipName的值要与rom的zip文件名匹配。
        .dat文件内部的DrvName的值为借用哪个rom的加载方式，运行与DrvName匹配的rom时，可在"核心选项里"-"Romdata"处勾选借用它的Romdata(仅单选)。
        若RA根目录 /system/fbneo/romdata/里的.dat的文件名与对应rom名匹配，或 rom所在文件夹里有同名的.dat文件，则支持直接加载匹配zip文件。
        直接加载.dat文件，要求"运行所需rom资源"在"有效检索路径"里。
        
    4.运行rom时，若有与之匹配的IPS和Romdata,则可在RA "快捷菜单"的"核心选项"里看到 IPS 与 Romdata 菜单，ips可以选择多个，
      romdata只可选择1个(多选则随机其一)。启用后，在RA"快捷菜单"选择"重启"生效。
    
    5.游戏在IPS状态下运行，若"允许修补集组”为开启，则直接重启会恢复到原版，你可以在重启之前重新选择IPS，重启会转变为重新勾选的IPS版本。
      若重启游戏前关闭了"允许修补集组"功能，则重启会维持当前的IPS状态。
    
    6.若当前游戏以Romdata方式运行，"重启"依旧为Romdata状态。
    
    7.Romdata可与IPS叠加使用,即以Romdata方式运行的rom，可以在核心选项里选用IPS。
     (2025-07-08修订: 启动依赖Romdata的IPS的.dat，只要对应的romdata的.dat文件存在于BIOS目录的/fbneo/romdata/里，就能取得Romdata的支持)
   
    8.RA根目录 /system/fbneo/path 存放扩展路径配置，需要指定全路径。
      
      rom_path.opt : 指定直接加载ips或romdata的.dat文件时，除了默认有效路径，还能去哪里搜索运行所需rom资源。
         
      ips_path.opt 和 romdata_path.opt : 指定加载rom之后，核心菜单里对应IPS和Romdata菜单除了默认有效路径，还能去哪里搜索。
    
      以 rom_path.opt 为例，从0开始，最高到19
      
         linux系统    
        |----------------------------------| 
        |CoreRomPaths[0] /opt/bios/fbneo   |
        |CoreRomPaths[1] /opt/roms/fbneo   |
        |CoreRomPaths[2]                   |
        |----------------------------------|
         
         windows系统
        |----------------------------------|
        |CoreRomPaths[0] D:\roms\fbneo     |
        |CoreRomPaths[1]                   |
        |----------------------------------|
        
      ips_path.opt则为，从1开始，最高到19
        |----------------------------------|
        |CoreIpsPaths[1]                   |

七、与EmulationStation(ES前端)整合

    在 fbneo 的 rom 目录里新建一个 ips 文件夹，ips_path.opt 文件里添加这个 ips 文件夹的路径(使得 rom 启动的时候也会在这个文件夹检索对应的 IPS )，
    rom_path.opt 里添加 fbneo 的 rom 目录(使得启动 ips 的 .dat 文件的时候知道在哪个rom目录里找对应的 rom )，并且在加入核心时候添加 .dat 文件格式支持。
    这样就可以在ES前端启动 ips 的 .dat 文件。 
    
    ES前端不会扫描以点开头的文件夹，对于无法直接加载的需要搭配 romdata 才能运行的 ips，如果不想存放在 Retroarch 的 BIOS 路径下，可以新建 .ips 文件夹存放，
    并把路径添加进 ips_path.opt 文件里，ES前端不会把这些 ips 的 .dat 文件扫描进游戏列表里，但是核心选项的IPS菜单里依旧能找到。

八、街机ROM介绍

  一个街机游戏可能有多个地区版本美版，日版，亚洲版，国际版。
  有两种表现形式，1.个语言版本为一个游戏 2.多个语言版本都在一个游戏里，通过机台跳线设置切换地区语言。
  
  压缩包存储方式差异: 
  
    合并集(Merge)     :美版，日版，国际版的全部文件，都在一个压缩包中，也就是一个压缩包可以玩到所有版本的游戏。
                       合并集ROM内部文件的存在方式有两种情况: 1.当主ROM与子ROM的文件名没有冲突的情况下可以都堆在一起。
                       2.也可以在内部为子ROM新建一个与子ROM同名的文件夹存放差异部分的文件，即CRC在主ROM里没有的文件，特别是那些文件名重名但CRC不同的文件。
    
    非合并(Non Merged):美版，日版，国际版的全部文件，分别在不同的三个个压缩包中。而且都是完整的。比如玩美版就是用美版的压缩包，玩国际版就用国际版的压缩包。
    
    分离集(Split)     :国际版是主ROM压缩包，可以直接运行。美版，日版是子ROM，子ROM的文件不完整，必须要同时拥有主ROM才可以游戏。
    
    1.FBNEO核心无法直接使用合并集，需要新建文本文件改名为对应的子ROM的zip，利用分离集的处理方式从主ROM里加载文件。
    2.非合并的好处是单个压缩文件可以直接允许，没有依赖关系，没有BIOS文件找不到的问题，比较省心，占用存储空间较大。
    3.分离集是最常用的形式，能够节省不少存储空间。
  
  注: 街机模拟器的运行机制是通过ROM的压缩包文件名的确认是哪个游戏，再验证压缩包内的文件是否与游戏匹配，例如: kof97.zip 这个文件名一旦修改，模拟器就无法正确识别出这个rom是拳皇97。
  
      有的街机改版的作者仍在更新，改版ROM的更新，有可能使得zip压缩包名称的变更，压缩包内部文件的文件名，文件内容的变更，文件内容的变更会影响文件的大小和CRC校验码的值。
      这些更新使得街机模拟器版本与街机ROM之间存在明确的版本匹配关系。

  FBNEO核心与合并集ROM的使用: PC端的FBNEO支持合并集的ROM格式，可以通过内置的游戏列表加载对应的ROM文件。核心端没有列表，使用合并集就需要配合0KB的伪装ROM(即新建文本文档，然后重命名成子ROM，例如 kof98xx.zip)。
                              利用子ROM里找不到的文件会去主ROM里找的特性，加载到正确的子ROM。

九、IPS制作

    本教程只是IPS补丁制作的基本方法。

    IPS: 原版rom的改版补丁，[原版rom + IPS补丁 = 改版]。
         本质:加载ROM和IPS后，在内存里把补丁打上，然后运行。
            
      制作街机rom的IPS的前提条件
        1.改版rom里的文件要能与原版rom里的文件对应上。
        2.文件数量可以比原版少，但不能多。
        3.改版的文件大小不能超过原版文件的大小。
        4.单个文件超过16MB是不支持的
      
      街机rom是多文件的zip压缩包，生成补丁文件需要按照对应的文件提取补丁，需要将zip解压。
      
      本示例为 kof97.zip 拳皇97 与 kof97pls.zip  拳皇97风云再起 
      
          kof97.zip                          kof97pls.zip
         |----------|                       |------------| 
         |232-p1.p1 | <---------------------|kf97-p1p.bin|
         |232-p2.sp2| <---------------------|kf97-p2p.bin|
         |          |                       |            |
         |232-s1.s1 | <---------------------|kf97-s1p.bin|
         |          |                       |------------| 
         |232-c1.c1 |
         |232-c2.c2 |
         |232-c3.c3 |
         |232-c4.c4 |
         |232-c5.c5 |
         |232-c6.c6 |
         |          |
         |232-m1.m1 |
         |          |
         |232-v1.v1 |
         |232-v2.v2 |
         |232-v3.v3 |
         |----------|
       
      从文件名称可以看出，其对应关系，p1与p1p ,p2与p2p,s1与s1p
      判断对应的文件有没有被修改，只需检查两个zip压缩包里对应的文件的CRC的值是否相同，不同代表文件内容被修改了，需要创建IPS补丁
        
      常用的IPS提取工具 "Lunar IPS.exe"
        Apply IPS Patch  是把 IPS补丁打入原版文件，
        Create IPS Patch 从原版文件和改版文件中提取IPS补丁
      
        启动 "Lunar IPS.exe" 选择 "Create IPS Patch" ，
        将弹框限定的文件类型从"Most Common Rom Files"修改为"All Files(*.*)"  
        此处会要求你选择两次文件，先选择原版文件再选择对应的改版文件。
        
        先选 232-p1.p1 ,在选择 kf97-p1p.bin，就能够生成对应的.ips文件，保存为 kf97-p1p.ips
        把另外两个的ips文件 kf97-p2p.ips，kf97-s1p.ips 也生成出来。
        
        这些补丁文件可以通过"Apply IPS Patch" 打进原版rom将原版rom转化成改版rom，这种方式运行时如果有CRC校验会报错。
      
      ★FBNEO提供了加载原版rom并应用IPS补丁的方式，只要原版rom是可运行的，就可以运行从它身上提取的IPS。
      
        需要创建一个.dat文件，文件编码UTF8，把所需的.ips文件及其对应关系标注出来。.dat文件名里不要包含下划线或多个点("_",".")
      
        kof97pls.dat  文件内容如下
         
         |---------------------------------------------|  
         |232-p1.p1    kf97-p1p     CRC(7DB81AD9)      |
         |232-p2.sp2   kf97-p2p     CRC(158B23F6)      |
         |232-s1.s1    kf97-s1p     CRC(8514ECF5)      |
         |                                             |
         |[en_US]                                      |
         |The King of Fighters '98 / Feng Yun Zai Qi   |   这里是IPS的名称
         |The King of Fighters '98 Feng Yun Zai Qi     |   这里是IPS的说明
         |                                             |
         |[zh_CN]                                      |
         |拳皇98 / 风云再起                            |
         |拳皇98的改版，无限能量，解锁隐藏人物。       |
         |                                             |
         |[zh_TW]                                      |
         |拳皇98 / 風雲再起                            |
         |拳皇98的改版，無限能量，解鎖隱藏人物。       |
         |---------------------------------------------|
         
        先列举原版rom文件需要带后缀名，再列举对应的ips文件，不需要后缀名。此处只列举需要打ips补丁的文件。
        对应原版rom的文件的CRC项(即 "CRC(7DB81AD9")可以不写，CRC是为应对原版rom的文件名变更的补偿匹配方式。
        如果恰好是两个或以上具有相同CRC的空白扩容文件都发生了文件名变更导致匹配不上，此时CRC的补偿匹配机制就会出问题，这是极小概率会发生的事件。
        IPS的名称标注,可以只标注一个,[en_Us]表示英文名,[zh_CN] 表示简体中文名，[zh_TW] 表示繁体中文名,前面不能有空格。
        另起一行写对应的名称,斜杠表示子分类(子分类只在独立版模拟器里有效)
        再起一行写对应的文字说明
          
        拳皇97风云再起的IPS就制作好了。 
        
        新建 kof97 文件夹，文件夹名称需要与对应的原版rom匹配把 kof97pls.dat, kf97-p1p.ips, kf97-p2p.ips, kf97-s1p.ips 放进去
    
        .ips文件的相对路径存放
          在kof97文件夹里面创建一个文件夹kof97pls存放.ips文件，外面存放.dat文件，此时.dat文件里的列表需要修改为对应的相对路径
          |---------------------------------|
          | 232-p1.p1    kof97pls/kf97-p1p  |
          | 232-p2.sp2   kof97pls/kf97-p2p  |
          | 232-s1.s1    kof97pls/kf97-s1p  |  
          |---------------------------------|
    
    ★多个ips改版的组合
      通过上面的示例，不难发现一个IPS的改版对应的是一组ips文件列表，那么只需要新建一个.dat文件，把多个.dat文件里的ips列表复制到一块，
      多IPS组合的改版就被制作出来了。
      如果有一个特定的IPS组合经常玩，每次都要去核心选项里勾选多个很麻烦，就可以通过这种方式制作成一个专门的组合型改版。
      也可以通过Lunar IPS 工具，把多个改版的IPS补丁都打入原版rom中，生成一个组合改版，再提取出IPS补丁。
      
      注: .ips格式的文件名不要使用中文，文件名存在空格的是使用英文的双引号括起来

    IPS的使用
  
      1.Windows版本FBNEO模拟器使用IPS补丁的方法，把kof97文件夹复制到 FBNEO模拟器根目录/support/ips/里
        载入游戏，左侧选中拳皇97，点击右侧的IPS管理器，勾选需要的使用的IPS，确定。把右侧的"应用补丁"勾上，进入游戏。
      
      2.FBNEO_PLUS 核心使用 IPS 的方法，把存放ips的kof97文件夹复制到Retroarch根目录/system/fbneo/ips/目录内，
        加载kof97.zip, RA "快捷菜单"->"核心选项"-> "允许修补集组"设置为"开",在"IPS 补丁"里开启"拳皇98 / 风云再起",返回快捷菜"重启"游戏。
        
      3.直接加载.dat文件，要求"运行所需rom资源"在"有效检索路径"里。
      
      4.启动依赖Romdata的IPS的.dat，只要对应的romdata的.dat文件存在于BIOS目录的/fbneo/romdata/里，就能取得Romdata的支持。

十一、Romdata制作
   
    Romdata: 借用已收录的rom加载流程，替换驱动定义，使得rom能够运行，[未定义的rom + Romdata定义 = 可识别运行]，
             本质:临时替换被借用的ROM的驱动列表，当作那个ROM来运行。
             运行Romdata不需要被借用的rom的zip文件参与，且不适用于被第三方特殊加密过的rom。
  
    IPS搞不定的rom，可以尝试通过romdata方式解决。
         
    libretro_fbneo 项目地址 https://github.com/libretro/FBNeo
    
    编写Romdata的.dat文件，需要具备一定代码阅读理解能力。
    需要熟悉libretro_fbneo项目\src\burn\drv\目录内的每一个机种目录里以 "d_" 开头的.cpp文件里的驱动定义格式。
  
    ★Romdata的运行逻辑: 加载zip文件，判断文件名是是否为默认可运行的rom，如果是，则按照默认的流程加载，如果不是，
    则在当前加载的zip所在目录和RA根目录下/system/fbneo/romdata/处寻找是否有同名的.dat文件，没有则加载失败,有则
    进入Romdata的加载流程，ZipName处指定改版的zip文件名，DrvName处指定借用哪个可运行Rom的加载流程，用.dat文件
    中新定义的驱动文件列表，临时替换掉被借用的rom在源代码中定义驱动文件列表，把当前加载的rom当作被借用的rom来运行。
    
    基于这个判断机制，使用Romdata加载zip文件，zip文件名需要与dat文件同名，且zip文件名不能与官方默认可运行的rom重名。 
    
    本示例为  oldsplusnr211.zip  西游释厄传-群魔乱舞v211为，文件内需要使用英文标点符号。

    新建 oldsplusnr211.dat 文件，文件编码UTF8，参考oldsplus的驱动列表，仿写 oldsplusnr211.zip 的驱动列表，其实就是复制过来改。
    改版rom的文件名称与原版文件的名称具有一定的相似性的，把文件名、大小、类型 对应上，文件顺序不能乱。
  
    方框里为oldsplusnr211.dat 的文件内容。.dat文件名里不要包含下划线或多个点("_",".")

      | "igs_w05301nab032.u5",    0x0400000,   0x00000000,    5 | BRF_SND                            |
      | "oldsplus_igs027a.bin",   0x0004000,   0x00000000,    7 | BRF_PRG | BRF_ESS | BRF_NODUMP     |

      ==========================================================================
        ZipName:  不在游戏列表中的Zip名称，即要运行的改版rom
        DrvName:  选择游戏列表中存在的驱动程序，即借用哪个rom的加载流程
        ExtraRom: NeoGeo 特定的额外 rom , 没有的话这一行可以不写
        FullName: 游戏的详细名称
        romname:  zip里的文件名称
        romsize:  文件的大小，数值是zip压缩包内大小的数值从十进制转十六进制的值 
                  8388608 十进制转十六进制值为 800000
                  4194304 十进制转十六进制值为 400000        
        crc:      每个文件对应的CRC。如果需要在Romdata的基础上叠加使用IPS，务必写上正确的CRC; 如果只是运行某个ROM本身，可以写0或0x00000000。
        type:     驱动类型参照源码即可
      ===========================================================================
      
    oldsplusnr211.zip 的主ROM为 oldsplus.zip 。按照分离集ROM的思想，主ROM的type为7的这一段没有被子ROM覆盖，那么 oldsplus_igs027a.bin 文件会被子ROM继承。
    所以oldsplusnr211.zip完整的驱动列表应该补充上 oldsplus_igs027a.bin 的定义。DrvName为oldsplus，直接借用主ROM加载流程，即把oldsplusnr211.zip当作主ROM来运行。
    那么就不存在去主ROM里找文件的过程，缺失的oldsplus_igs027a.bin文件就需要从oldsplus.zip里复制一份到 oldsplusnr211.zip里，把ROM补充完整,即子ROM转主ROM。
    若借用的是相同主ROM的其他子ROM(例如 DrvName: oldsplus203)的加载流程，则不需要把ROM补充完整，只需要确保同目录下有主ROM(oldsplus.zip)存在就行。

    实际上 oldsplus.zip 里同样没有 oldsplus_igs027a.bin 且驱动列表中对应的CRC值为0x00000000，类型为 BRF_NODUMP 代表这是一个不存在的文件。
    这种情况下根主ROM一样没有即可。Romdata里  "oldsplus_igs027a.bin" 这一行可写可不写，不影响游戏运行。
    
    补充说明: 
      通过从源码里复制驱动列表的方式编写romdata 驱动行两端的大括号和逗号是不会影响Romdata加载的，但是后面两个斜杆的注释内容必须删除
      示例:  { "v-205cn.u10", 0x0400000, 0x923f7246, 1 | BRF_PRG | BRF_ESS },  //  0 68K Code   此行内容后面的 "//  0 68K Code" 需要删除，两端的大括号和结尾的逗号无影响
      即: { "v-205cn.u10", 0x0400000, 0x923f7246, 1 | BRF_PRG | BRF_ESS }, 与  "v-205cn.u10", 0x0400000, 0x923f7246, 1 | BRF_PRG | BRF_ESS 是等价的。
      文档说明中的oldsplusnr211.dat，为了内容简洁，删除两端的大括号和结尾逗号。

      在FBNEO PC客户端中，可以在游戏列表右键指定的游戏，选择导出该游戏的Romdata模板。
      导出模板的Type值使用的是以"0x"开头的直接值，"0x01100001" 与 源码中的 "1 | BRF_ESS | BRF_PRG" 是等价的    
    
      改版的rom文件数量可能与原版不一致，可以参照原版rom的其他改版的驱动列表进行编写。
      Romdata的加密解密处理要与被借用的rom加载流程匹配。
      
      例如 kof2k2 [拳皇2002原版] 加载有解密流程 ， kof2k2fd [拳皇2002解密版] 加载则不含解密流程。
      由于kof2k2fd并非以主Rom的形式存在，其继承自kof2002，借用kof2k2fd的驱动还得检查kof2002这个主Rom是否存在，在rom内容完整的情况下这个主Rom检查是有点多余的。
      源码中，BurnDrvKof2k2fd的加载流程设置与BurnDrvKof97基本是一致的，即无加密的拳皇2002改版在rom内容完整的情况借用kof97反而是更加直接的。
      如果改版rom是无加密的，则需借用解密版的加载流程。
      
      PGM有些三国战记的改版的第一部分即P-rom是未加密的，表现在zip压缩后的文件体积比较小。
      未加密的kovshp系列可以直接借用kovassg的加载流程，这个rom是没有解密流程的。
      
      当被借用的ROM加载流程本身是带解密的，此时就需要将未加密的部分替换为加密后的，才能正确借用。 
      例如借用kovshp的驱动就需要先对P-rom进行kovshp对应的加密。
      
      关于拳皇游戏时间瞬间归零问题，拳皇系列许多改版的加载流程有时间补丁处理: kof97TimePatch(),kof98TimePatch(),kof99TimePatch(),kof2002TimePatch()。
      在d_neogeo.cpp这个文件中kof97plc这个改版就使用了kof97TimePatch, 通过romdata加载97的改版如果出现时间瞬间归零问题，则可以考虑将借用的驱动变更为kof97plc

十三、扩容rom的构建
 
  扩容ROM的作用: 承载扩容改版ROM的IPS补丁的基底ROM。
  
  有些改版游戏需要使用更多的图片与声音的素材资源，原版ROM的空间不足以放下，因此这些改版ROM的文件大小和数量会超过原版，这样就无法通过原版ROM直接提取IPS补丁，
  需要把原版ROM扩容的成相同文件数量和大小的扩容ROM来提取IPS补丁，这些补丁需要应用到扩容ROM上才能被正确加载。
  
  扩容rom的名称不要和FBNEO已有的rom名重复，否则zip文件无法通过Romdata的方式正确加载。

  扩容多出来的文件一般是由0xFF 或 0x00 填充的二进制文件。
  
  在当前目录输出由0xFF 填充的8MB和4MB的空扩容文件。 
    
    "创建0xFF填充的8MB和4MB的空扩容文件.ps1"
    |---------------------------------------------------------|
    |  # 设置要创建的文件大小（以字节为单位）                 |
    |  $fileSize8MB = 8 * 1024 * 1024  # 8MB                  |
    |  $fileSize4MB = 4 * 1024 * 1024  # 4MB                  |
    |                                                         |
    |  # 创建一个8MB的文件并填充为0xFF                        |
    |  $file8MB = "8MB_file_filled_with_0xFF"                 |
    |  $buffer = new-object byte[] $fileSize8MB               |
    |  for ($i = 0; $i -lt $fileSize8MB; $i++) {              |
    |      $buffer[$i] = 0xFF                                 |
    |  }                                                      |
    |  [System.IO.File]::WriteAllBytes($file8MB, $buffer)     |
    |                                                         |
    |  # 创建一个4MB的文件并填充为0xFF                        |
    |  $file4MB = "4MB_file_filled_with_0xFF"                 |
    |  $buffer = new-object byte[] $fileSize4MB               |
    |  for ($i = 0; $i -lt $fileSize4MB; $i++) {              |
    |      $buffer[$i] = 0xFF                                 |
    |  }                                                      |
    |  [System.IO.File]::WriteAllBytes($file4MB, $buffer)     |
    |                                                         |
    |  # 输出成功消息                                         |
    |  Write-Host "Files created successfully."               |
    |---------------------------------------------------------|
  
  右键powershell执行脚本文件即可生成对应大小的扩容用的文件。
  
  如果只是给rom增加扩容文件，只需把扩容文件修改成需要的名称添加进zip里，并在Romdata的.dat文件里添加该文件即可。
  
  如果是扩容原本就存在的文件大小，需要使用到下面的脚本，同样是右键powershell执行，先拖入模板文件回车，再拖入未扩容的原文件回车，就能生成扩容后的文件，重命名成需要的名称即可。

    |----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|

    | $sourceFile = Read-Host "Drag and drop the source file here"                                                                                                                           |

    | # 读取文件内容                                                                                                                                                                         |
    | $sourceContent = [System.IO.File]::ReadAllBytes($sourceFile)                                                                                                                           |

    |                                                                                                                                                                                        |
    | # 确保源文件的大小不超过目标文件的大小                                                                                                                                                 |
    | if ($sourceContent.Length -gt $targetContent.Length) {                                                                                                                                 |
    |     Write-Host "Source file is larger than the target file. Cannot overwrite." -ForegroundColor Red                                                                                    |
    |     exit                                                                                                                                                                               |
    | }                                                                                                                                                                                      |

    | # 创建目标文件的副本                                                                                                                                                                   |
    | $targetCopyFile = Join-Path -Path (Split-Path -Path $targetFile) -ChildPath ("$([System.IO.Path]::GetFileName($sourceFile))_extend$([System.IO.Path]::GetExtension($targetFile))")     |
    |                                                                                                                                                                                        |
    | # 复制并写入源文件内容到目标文件的副本                                                                                                                                                 |
    | try {                                                                                                                                                                                  |
    |     [System.IO.File]::Copy($targetFile, $targetCopyFile, $true)                                                                                                                        |

            "ZX Spectrum",                         - "spec_"
            
  3.子系统的IPS使用

     家用机游戏的rom基本都是单文件，此处以SFC的游戏《电精》为例，压缩包名称为"gcdenseij.zip" 内部文件名为 "Ghost Chaser Densei (J)(1994)(Banpresto).sfc"
     
     子系统的rom的IPS目录需要使用对应的"子系统前缀"才能正确匹配,对应的IPS目录为 /system/fbneo/ips/snes_gcdenseij/ ， 此处 "snes_"前缀是关键。
     
     即便的单文件的IPS，同样需要.dat文件作为引导文件。
     电精高亮的IPS文件为 "GCD - Brightness Fix.ips" 
     内容如下: 
       |---------------------------------------------------------------------------------------------|
       |"Ghost Chaser Densei (J)(1994)(Banpresto).sfc"    "GCD - Brightness Fix"  CRC(DFD6385D)      |
       |                                                                                             |
       |[en_US]                                                                                      |
       |Brightness Fix                                                                               |
       |                                                                                             |
       |[zh_CN]                                                                                      |
       |亮度增强                                                                                     |
       |---------------------------------------------------------------------------------------------|
     
     IPS列表需要写zip内部带后缀的文件名，文件名存在空格建议用英文的双引号包裹，文件名准确的情况下可以不写后面的CRC，
     CRC可以在文件名不匹配的情况下通过CRC匹配。
     
     注: 1.使用的IPS必须是从官方支持的原版rom上提取，且改版rom和原版rom的文件大小一致才能确保IPS的有效性。
         2.ips文件名的名称不要包含中文 ！！！
       
  4.子系统Romdata的创建与使用
    
    汉化游戏由于需要添加额外中文字库，rom文件大小是难以与原版rom保持一致的，此时就需要通过Romdata的方式来运行。
    
    以SNES的电精汉化高亮版为例，压缩包名为 "gcdenseicnbf.zip"
    
    zip内容为
      |--------------------------------------------------------|
      |名称                             大小       CRC         |
      |gcdensei(CN)Brightness_Fix.sfc   3145728    9195C287    |
      |--------------------------------------------------------|
    
    Romdata文件 内容如下: 
      |-------------------------------------------------------------------------------------|
      |  ZipName: snes_gcdenseibfcn                                                         |
      |  DrvName: snes_gcdenseij                                                            |
      |  ExtraRom:                                                                          |
      |  FullName: "电精 汉化高亮版"                                                        |
      |                                                                                     |
      |  // romname,                        romsize,       crc,    type                     |
      |  gcdensei(CN)Brightness_Fix.sfc,    0x300000,      0,      BRF_ESS | BRF_PRG        |
      |                                                                                     |
      |-------------------------------------------------------------------------------------|
    
    子系统的romdata文件内 ZipName需要补充子系统的前缀，借用日版电精的驱动gcdenseij时同样需要补充个子系统前缀
    底下的驱动则从SNES的源码驱动文件 d_snes.cpp 把gcdenseij的驱动定义复制过来修改一下即可，
    romname需要写zip里的原文件名，大小仍然为十进制转十六进制后的值
    
    注: 家用机 nes，snes，md 都是支持romdata的

  5.NEOGEO-CD (NEOCD)的使用
    
    (1)BIOS文件

       使用FBNEO游玩NEOCD，需要准备的BIOS文件 neogeo.zip 和 neocdz.zip 存放在有效检索路径里。
       a.在PC端FBNEO独立版，放置于客户端根目录下的/roms/arcade目录
       b.在RetroArch端则放置于RetroArch的BIOS目录 或 与游戏同目录，游戏目录名建议使用neocd，这样可以直接加并应用NEOCD子系统。
    
    (2)★游戏Rom的准备

       NEOCD的游戏ROM 一般为 单个CHD 或 .CUE+多个.BIN或其他格式的多文件形式，FBNEO似乎只支持 .CUE+单个.BIN 的格式。
       可以通过chdman转换工具，先将CUE+多个BIN的 ROM文件转换成单个CHD文件，再通过chdman工具将CHD文件转成 CUE+单个BIN的形式
       
       chdman 批处理bat脚本如下(chdman存放路径不要有中文):
       
         CUE-GDI-ISO to CHD.bat    将当前目录下的CUE或GDI或ISO转换成CHD
           for /r %%i in (*.cue, *.gdi, *.iso) do chdman createcd -i "%%i" -o "%%~ni.chd"
         
         Extract CHD to CUE.bat    将当前目录下的CHD转换成CUE
           for /r %%i in (*.chd) do chdman extractcd -i "%%i" -o "%%~ni.cue"
         
    (3)NEOCD rom的放置与加载

       a.PC端FBNEO独立版，将CUE和BIN文件放置于客户端根目录下的/neocdiso目录，
          启动游戏的方式
          方式一 启动FBNEO客户端，菜单栏选择"游戏"-"载入NEOGEO CDZ游戏"，如果存放在/neocdiso目录时ROM套了一层文件夹，此处需要勾选"扫描子目录"，选中对应的游戏运行。
          方式二 启动FBNEO客户端，菜单栏选择"游戏"-"选择CD镜像(CUE/CCD)" 加载CUE文件，菜单栏选择"游戏"-"启动NEOGEO CDZ", 此方式支持未被收录的游戏。
          备注：2026.6.21 FBNEO PC客户端支持chd格式的rom

       b.RetroArch端允许任意目录存放ROM，推荐将neogeo.zip,neocdz.zip 以及ROM的.bin和.cue文件放置在同一个目录内，游戏目录命名为"neocd"，目录名"neocd"称会使得FBNEO核心自动适配NEOCD子系统运行游戏。
         运行方法参照"在Retroach中使用FBNEO家用机子系统"的两种方式皆可。  
    
    (4)BIOS选择，启动游戏后，在"跳线设置"里可以切换不同的BIOS引导游戏启动，推荐使用 "NEOGEO CDZ" 这个兼容性好一些的BIOS
       a.PC端FBNEO独立版，启动FBNEO客户端只启动BIOS也可以修改BIOS设置，菜单栏选择"游戏"-"启动 Neo Geo CDZ" ,菜单栏选择"输入"-"跳线设置"-指定BIOS为"Neo Geo CDZ"
       b.RetroArch端启动游戏后按"F1"打开"快捷菜单"-"核心选项"-"跳线设置"-指定BIOS为"Neo Geo CDZ"
    
    (5)在BIOS启动CG播放时,按手柄键位里的A键可以中断游戏的加载进入BIOS菜单，在BIOS菜单里可以选择游戏的音轨播放，按手柄键位里的"START"则开始运行游戏
    
    (6)NEOCD的游戏内存档，PC端保存在根目录\config\games\neocdz.fs 文件里，RetroArch端为\saves\FinalBurn Neo\

十四、★IPS头部定义(此部分为高阶内容，文档尚不完善)

      头部定义的作用: 可以制作应用于原版ROM的扩容改版游戏的IPS补丁
      
      # 应用示例: SFC　火焰之纹章-圣战之谱系(汉化版)
      
      火焰之纹章-圣战之谱系 

          日文版文件大小 4194304 十六进制值 0x400000
          汉化版文件大小 4194816 十六进制值 0x400200
      
          两个文件的差值为  0x200
      
      汉化版比日文版大，使用 Lunar IPS 提取的IPS补丁直接应用运行会按照日文版的容量大小加载，加载内容缺失会导致游戏出问题或无法运行。
      
      火焰之纹章-圣战之谱系 日文版 在d_snes.cpp中的驱动定义如下
      
        "Fire Emblem - Seisen no Keifu (Japan)(1996)(Nintendo).sfc", 4194304, 0xdc0d8cf9, BRF_ESS | BRF_PRG
      
      可以看出家用机一般都对应程序段 BRF_PRG
      
      此时就需要使用IPS的头部定义增加PRG的加载大小，此处增加0x200   #define IPS_PRG1_EXPAND  0x200 (此处写0x100000也是可以的，够用就行)
      
      如果是MD游戏一般到此就可以了，但SFC游戏有VRAM访问限制，有的SFC汉化不解除限制会导致菜单乱码。
        
        在d_snes.cpp中的解除VRAM访问限制的相关代码如下
        
        1.解除VRAM访问限制的DIP跳线选项对应  SNESVRAMHackDIPInfo
          static struct BurnDIPInfo SNESVRAMHackDIPList[] =
          {
              DIP_OFFSET(0x19)
              {0x00, 0xff, 0xff, 0x01, NULL            },
              {0x01, 0xff, 0xff, 0x00, NULL            },
              {0   , 0xfe, 0   ,    2, "Allow vram writes outside blanking (hack)" },
              {0x00, 0x01, 0x01, 0x00, "Off"                },
              {0x00, 0x01, 0x01, 0x01, "On"                },
          };
          
        2.解除VRAM访问限制初始化对应  VRAMHackInit
          static INT32 VRAMHackInit()
          {
              if (!bDoIpsPatch && (NULL == pDataRomDesc))
                  DrvDips[0] = 1;
              return DrvInit();
          }
